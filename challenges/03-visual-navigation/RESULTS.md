# Luna 单分叉实际运行结果

单分叉采用 Isaac Sim 6.2、Nova Carter、Humble Nav2 MPPI 和官方 Responses API `gpt-6-luna`。两个场景使用相同的地图、规划参数和公开中性候选，交换蓝色 B 与橙色 A 的标牌位置。任务始终要求通过蓝色 B 对应的通道。模型收到实际车载 PNG。独立 PhysX 评估离线复验执行路线和低速驻留。

| 录制试次 | 结果 | 终点误差 | 独立物理证据 |
| --- | --- | --- | --- |
| 20261121T065948Z-a38ea9a2 | Luna 选择右侧 c24，实际通过 c24 | 0.172 m | 平面行程 11.64 m，驻留峰值 0.0084 m/s，非地面接触 0 |
| 20261121T070119Z-9b0c72bd | Luna 选择左侧 c71，实际通过 c71 | 0.209 m | 平面行程 11.56 m，驻留峰值 0.0043 m/s，非地面接触 0 |
| 20261121T070248Z-949da2e7 | 50 ms API 时限触发真实传输超时 | — | 无控制请求，超时后 4.00 墙钟秒内平面速度峰值 0.00082 m/s |

原始运行目录在工作区 `p4-live-evidence` 的 `videos-original`、`videos-swapped` 和 `videos-timeout` 下。每个目录保存启动清单、模型帧及哈希、原始响应或传输错误、ROS 日志、PhysX 轨迹与接触、独立展示相机原始帧和时间索引。生成、编码和复核命令见 [README](README.md)。

两个正常录制试次各有独立带字幕 MP4 与同步交互回放。字幕按同次试验时间戳添加，整个片段从同一原始视频以 1× 墙钟速度导出，无剪接。原始视频分辨率为 896×504。两条正常路线各录得 719 帧和 680 帧，实际约 11.40 帧/秒和 11.14 帧/秒。编码 PTS 与墙钟帧索引最大偏差小于 1 ms。录制时，五秒窗口 RTF 中位数为 0.963 和 0.956，p5 为 0.915 和 0.816。此前无录制试次的中位数为 1.107 和 1.081。采集低于 30 帧/秒目标，录制开销与换牌 p5 也未达到规格的实时展示门槛。

两种录像版语义对照由 `evaluator/live_pair.py` 复算并写入 `p4-live-evidence/recorded-live-pair.json`。超时独立证据为超时试次的 `timeout-evaluation.json`。录像与控制频率数据见 `p4-live-evidence/recording-metrics.json`。离线回放还覆盖模型等待、视觉结果、本地过期拒绝和请求超时。工作区 `attempts.jsonl` 保留早期底盘卡滞、TF 获取超时和视觉过期等失败。

本轮验证范围是单分叉。运行时换门、ROSClaw daemon 注册、终点标识互换、完整多场景与六集预登记验收仍见 [交接清单](HANDOFF.md)。


## 单通道连续改路追加验收

同一单分叉额外完成四次实车仿真，累计验证八次无驻留的路径交接。一组使用官方 Luna 看图确定 c71，另一组用固定 c24 控制指令。每次保持最初通道承诺，完成两次 FollowPath 预占式接续并忽略真实旧动作回执。延迟验证使用一条实际规划结果，测试程序控制其投递时机。两次取消试次都在完全通过选定门区后停车。正常的 Luna 试次录像和回放位于 `p3-continuous-evidence/luna-swapped/20261121T073007Z-99cf21d0`。独立评估汇总见 `p3-continuous-evidence/summary.json`。


## 动态遮挡触发同会话重新观察

试次 `20261121T105949Z-fd238476` 中，卷帘在仿真 7.02 秒开始打开，8.80 秒完全打开。第一次 API 使用 4.90 秒真实图像，Luna 返回 `reobserve`。第二次使用 10.80 秒新图像，实际返回 `select_candidate c71`。两张图像哈希与两条官方响应均可复验。第一次请求至 FollowPath 提交前，PhysX 平面速度峰值为 0.00082 m/s。此后车辆通过 c71、两次连续交接并在距终点 0.232 m 处停稳，非地面接触为零。

试次 `20261121T110142Z-63e1f4c2` 将预算限制为一次。首帧返回 `reobserve` 后进入 HOLD，没有提交导航动作。遮挡试次验证的是出发前的动态可见性，不覆盖行驶中突然横穿、封路后的重新换门和恢复。证据位于工作区 `p8-reobserve-evidence`。

## 行驶中封堵与自适应恢复

同一程序从当前 LaserScan、TF 和 Nav2 完整代价地图识别路径受阻。场景配方只改变 Isaac 中的障碍物位置，决定停车或恢复的控制逻辑只读取传感器、任务规则与运行期限。新地图持续显示受阻后先取消活动动作，再独立检查 PhysX 低速驻留。保留原通道时使用新观测和局部、全局地图重新验证。若任务明确允许替代，重新采集 RGB-D，再向 Luna 请求新候选。发起恢复运动前仍检查局部足迹与活动通道。

早期试次揭示两类恢复失败。暂时封堵解除后，滚动代价地图的旧障碍会妨碍 MPPI。恢复现在只在驻车后刷新该层，并要求扫描与两次完整滚动地图更新均已推进。持久封堵后直接切到相反方向曾因底盘仍朝向原通道而无法形成进展。换路现在可在已验证的空闲停靠范围内转向，确认低速和里程计位移，再根据修正后的地图姿态重新规划。所有失败与新试次证据都保存在工作区 `p9-adaptive-evidence`。
